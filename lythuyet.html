Trả lời phần lý thuyết

Đề thi kết thúc học phần Lập trình Web, đề số 1 (40 điểm).

Câu 1. Khác biệt giữa position: absolute và position: relative (10 điểm)

Khác biệt:

Tiêu chírelativeabsolute
Luồng hiển thị (normal flow)Vẫn nằm trong flow, vẫn chiếm chỗ ở vị trí gốcBị gỡ khỏi flow, không chiếm chỗ
Mốc định vịChính vị trí gốc của nóAncestor (tổ tiên) gần nhất có position khác static; nếu không có thì so với viewport/<html>
Tác dụng phụOffset (top, left...) chỉ dịch hiển thị, không đẩy phần tử khácPhần tử khác “chạy” vào chỗ trống, dễ chồng lấn

Tình huống dùng từng loại:

  • relative: dịch nhẹ một icon cho thẳng hàng với chữ (position: relative; top: 2px;) mà không làm các phần tử xung quanh xê dịch, và làm “mốc” cho phần tử con absolute.
  • absolute: nhãn giảm giá ở góc card, menu thả xuống (dropdown), tooltip, lớp phủ (overlay) đặt đè lên một phần tử khác.

Ví dụ tạo layout responsive: card sản phẩm có nhãn giảm giá.

.card  { position: relative; }
.badge { position: absolute; top: 8px; right: 8px; }

.card dùng relative làm mốc cho phần tử con. Card co giãn theo Flexbox/Grid thế nào thì nhãn .badge vẫn bám đúng góc card, vì mốc định vị là .card chứ không phải viewport.

Ảnh hưởng khi deploy lên hosting: position là CSS chạy ở phía client (trình duyệt), hosting chỉ phục vụ file tĩnh nên không ảnh hưởng đến quá trình deploy. Cái bị ảnh hưởng là độ tương thích trên các thiết bị khác nhau: nếu dùng absolute với giá trị px cố định cho layout chính thì trên màn hình nhỏ sẽ bị chồng lấn hoặc vỡ bố cục. Cách xử lý:

  • Layout chính dùng Flexbox/Grid; absolute chỉ dùng cho badge, tooltip, dropdown, overlay.
  • Khai báo <meta name="viewport" content="width=device-width, initial-scale=1">, dùng đơn vị %/rem và media query.
  • Kiểm tra bằng Device Toolbar của Chrome DevTools trước khi deploy.

Câu 2. Quy trình đăng ký domain và cấu hình hosting (10 điểm)

Quy trình:

  1. Đăng ký domain: chọn registrar (nhà đăng ký tên miền) như Namecheap, GoDaddy, PA Vietnam; kiểm tra tên còn trống và trả phí theo năm.
  2. Chọn static hosting (hosting file tĩnh) vì website chỉ gồm HTML/CSS/JS chạy phía client, sau đó đẩy code lên (GitHub Pages, Netlify).
  3. Cấu hình DNS: với domain gốc (example.com) tạo bản ghi A trỏ tới IP của hosting (GitHub Pages dùng 4 IP từ 185.199.108.153 đến 185.199.111.153); với subdomain (www) tạo bản ghi CNAME trỏ tới username.github.io hoặc site.netlify.app.
  4. Khai báo custom domain trên hosting (GitHub: Settings → Pages → Custom domain; Netlify: Domain management).
  5. Chờ DNS propagation (lan truyền DNS, từ vài phút đến vài giờ tùy TTL), sau đó bật HTTPS (hosting tự cấp chứng chỉ Let’s Encrypt).

Vai trò của DNS (Domain Name System): DNS giống như danh bạ của Internet, dịch tên miền dễ nhớ (example.com) thành địa chỉ IP. Trình duyệt hỏi resolver, resolver lần lượt hỏi root server, TLD server (.com) và authoritative nameserver để nhận bản ghi A/CNAME, từ đó có IP và gửi HTTP request tới hosting. Kết quả được cache theo TTL.

Hai công cụ deploy không cần server riêng:

  • GitHub Pages: push code lên repository, bật Pages để có link username.github.io/repo; miễn phí và tự động có HTTPS.
  • Netlify: kéo-thả thư mục hoặc kết nối repository Git, tự động deploy mỗi lần push, có sẵn HTTPS và quản lý domain.

Rủi ro bảo mật nếu cấu hình sai:

  • Không bật HTTPS: dữ liệu (form, cookie) truyền dạng plaintext, có thể bị nghe lén hoặc sửa đổi (MITM – Man-in-the-Middle).
  • Subdomain takeover (chiếm subdomain): để CNAME trỏ tới dịch vụ đã xóa, kẻ xấu đăng ký lại tên đó và chiếm quyền subdomain. Cần xóa record DNS khi ngừng dùng dịch vụ.
  • Lộ thông tin nhạy cảm: push API key hoặc file .env lên repository public thì ai cũng đọc được.
  • Mất quyền kiểm soát domain: tài khoản registrar/DNS không bật 2FA, hoặc để domain hết hạn bị người khác mua lại.
  • Cấu hình DNS sai (trỏ nhầm IP, wildcard thừa) có thể bị lợi dụng để phishing hoặc chuyển hướng người dùng.

Khai báo lạiCho phépKhôngKhông
Gán lại giá trịĐượcĐượcKhông (nhưng nội dung object/array vẫn sửa được)

Lỗi thường gặp: dùng var trong vòng lặp có callback bất đồng bộ.

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// In ra: 3 3 3 (mong đợi 0 1 2)

Nguyên nhân: var chỉ có một biến i dùng chung (function scope), đến khi callback chạy thì vòng lặp đã kết thúc với i = 3. Cách sửa: đổi sang let để mỗi vòng lặp có một binding riêng, kết quả in ra 0 1 2.

Lỗi liên quan TDZ: console.log(a); let a = 1; gây ra ReferenceError: Cannot access 'a' before initialization.

Debug bằng Chrome DevTools (F12):

  • Console: đọc thông báo lỗi và dòng gây lỗi.
  • Sources: đặt breakpoint (điểm dừng) trong callback, dùng F10 (step over) hoặc F11 (step into) để chạy từng bước.
  • Panel Scope hiển thị giá trị biến theo Local/Block/Global; ở ví dụ trên thấy i = 3 ở Global nên nhận ra biến bị dùng chung.
  • Dùng Watch để theo dõi biểu thức, hoặc chèn debugger; vào code để dừng đúng chỗ cần kiểm tra.

Câu 4. Event Delegation trong JavaScript (10 điểm)

Khái niệm: thay vì gắn event listener cho từng phần tử con, ta gắn một listener duy nhất ở phần tử cha, dựa trên cơ chế event bubbling (sự kiện nổi bọt từ phần tử con lên các tổ tiên). Trong handler, dùng event.target (kết hợp closest()) để xác định phần tử con thực sự được tác động.

Ví dụ xử lý danh sách động (dynamic list):

<ul id="todo"></ul>
<button id="add">Thêm việc</button>

<script>
  const list = document.getElementById("todo");
  let n = 0;

  document.getElementById("add").addEventListener("click", () => {
    const li = document.createElement("li");
    li.textContent = "Việc " + (++n);
    list.appendChild(li); // thêm phần tử động
  });

  // Một listener duy nhất ở cha, xử lý cho mọi <li> (kể cả li thêm sau)
  list.addEventListener("click", (e) => {
    const li = e.target.closest("li");
    if (!li || !list.contains(li)) return;
    li.classList.toggle("done");
  });
</script>

/* CSS */
li.done { text-decoration: line-through; color: gray; }

Lợi ích khi tích hợp với HTML/CSS để tối ưu hiệu suất:

  • Chỉ cần một listener thay vì N listener nên tiết kiệm bộ nhớ, danh sách lớn vẫn nhẹ.
  • Phần tử thêm sau tự hoạt động mà không cần gắn lại listener, tránh lỗi “item mới bấm không có phản hồi”.
  • Xóa phần tử không cần removeEventListener, giảm nguy cơ memory leak (rò rỉ bộ nhớ).
  • JS chỉ đổi class (hoặc đọc thuộc tính data-* để biết item nào), phần hiển thị do CSS đảm nhiệm, giúp tách biệt logic và giao diện, code gọn hơn.

Lưu ý: các sự kiện không bubble (như focus, blur) phải dùng focusin/focusout; nếu phần tử con gọi stopPropagation() thì delegation sẽ bị chặn.
